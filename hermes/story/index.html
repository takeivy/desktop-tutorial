One record, six moves

Every step updates the same request, so staff, crews and residents all see the same status.

  1. 1ReportA resident reports it once, in about a minute.
  2. 2ReviewA person checks it before any work starts.
  3. 3Hand offOnly approved requests move to the crew.
  4. 4RouteThe workflow sets the steps and the owner.
  5. 5RespondThe crew fixes it and closes it on a phone.
  6. 6RevealStaff and the public see the same result.

Who sees whatOne record

Same data, the right view

Nobody re-types a report. Each group simply looks through a different window.

  1. ResidentsReport form viewAdd a report. They never see anyone else’s details.
  2. Reviewers and crewsStaff Edit ViewEverything needed to do the work, including how to reach the reporter.
  3. The publicOpen ViewIssue type, place, status and dates. No names, no emails.
  4. The ownerSource layerFields, settings and the scheduled hand-off.

Residents’ names and emails stay with staff. The public sees progress, never people. And a status changed in one place changes everywhere.

The point
One report. Nobody re‑typed it. Nobody chased it.

And the resident never had to call to ask where it was.

  • Status changes are written by the system, not typed by a person.
  • The public sees the same truth as staff, minus the staff-only fields.
